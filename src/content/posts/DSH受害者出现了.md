## 起因

想给飞书连接dsh的插件加图片推送功能。让dsh自己去修改，然后就上班去了。过了两个小时吧，中间还使用飞书准备派活给dsh，结果提示还有任务执行中，需要排队，当时还以为是插件被改坏了。

结果晚上下班回来，打开 DSH 一看——那个会话还在跑。

立即感觉天塌了。

点进会话，屏幕上密密麻麻全是工具调用记录，同一条命令刷了几千行。右上角重试次数还在跳。它没在干活，它在原地转圈。

我赶紧点击终止，登 Token Plan 后台。个人版额度本来还剩 35%，加上一个 100% 的扩容包，怎么着也够撑一周。现在只剩 15%。当天的 token 消耗柱状图，一柱擎天，把前后几天衬成了地平线。

11 个小时。4616 步。3695 次 PowerShell 调用，其中 3617 次是同一条命令。

## 发生了什么？

我去分析了那个失控会话的日志，还原了全过程。

前两个小时是正常的。读源码、定方案、写代码、派子 agent 做审查——一个标准的开发流程，干得挺像样。

转折发生在第 5517 条日志。它做了一次上下文压缩。

压缩完之后，第 5522 条开始扫 session 目录。第 5543 条起，进入死循环：同一条 pwsh 命令，遍历所有会话文件夹读 .zstd 文件大小，一遍又一遍。

整个 4616 步里，模型没有输出过一句人话。每一步只有工具调用，没有文字，没有思考过程。它不是在思考后决定再试一次，它是在无意识地重复。

## 为什么会这样

三层原因叠在一起。

第一层：压缩销毁了犯罪证据。

DSH 的上下文管理插件会在对话变长时自动压缩历史。94 次 compress 把三千多次重复调用的结果压成了一句摘要。模型看到的上下文里，最近几步永远像是「刚开始检查」——它看不到自己已经重复了三千次。

这就像一个人每做完一件事就失忆一次，然后醒来发现桌上有张纸条写着「检查一下会话状态」，于是又去检查。检查完又失忆。纸条还在。永远检查不完。

第二层：LLM 没有跨步记忆。

大模型的每一次决策完全由当前上下文窗口决定。它没有一个内部计数器记着「我已经调了 3617 次了」。上下文里看起来像第一次，它就当第一次做。这不是 bug，是架构决定的——Transformer 没有持久状态。

第三层：任务目标在压缩中模糊了。

原始任务是「给飞书加图片推送」。但经过多轮压缩，这个目标被摘要成了更泛化的描述。模型把「终验」理解成了「检查会话状态」，而「检查会话状态」是一个永远无法宣布完成的动作——你总能再检查一遍。

三层叠加的结果：一个没有刹车的车，司机失忆了，导航还坏了。

## 系统为什么没拦住

开始我还以为因为我使用的模型的问题，但后来经过agent 自己的分析，翻了 DSH 的源码。

agent-loop 的主循环是一个 while(true)。退出条件只有两个：用户手动中止，或者模型自己决定不再调工具。

没有步数上限。没有 token 预算。没有重复检测。

官方文档原话："There is no built-in turn budget." 没有内置的回合预算。想防跑飞？自己写插件。

设置页面里能调的只有「同时并行几个工具调用」，没有「最多跑几步」。三百多个官方插件，没有一个叫护栏、限额、熔断之类的名字。有个超时策略，但那管的是单次调用别卡太久，不管一整轮总共跑了多少步。

社区有人提过方案，做了分支版本，加了步数上限和重复检测。没合进主线。类似的反馈还有好几条：子 agent 跑了一千多次没人拦、任务完成后又重复跑了五十分钟、思考通道输出四万八千次重复短语。

不是没人遇到。是官方还没修。

## 怎么防止之后还发生

三件事。

一是给 agent-loop 写一个护栏插件。逻辑不复杂：同一条命令连续重复超过 N 次就强制中止；总步数超过阈值就中止；总 token 消耗超过预算就中止。社区那个分支版本的思路是对的，只是没人把它变成默认行为。

二是把「危险操作」和「只读操作」分开对待。读文件可以容忍多跑几步，写文件、发请求、执行 shell 命令必须有独立的确认机制或速率限制。

三是接受一个事实：当前的 AI agent 不是可靠的员工，是一个能力很强但没有常识的实习生。你不能给它一个模糊的任务然后指望它自己判断「够了」。你得替它设边界。


## 反思

我之前派任务给 AI，几乎从不考虑安全性。最多就是叮嘱一句：别把我的个人信息，比如银行密码，提交到 git 上。

但这次，11 个小时烧掉 85% 的额度，我意识到安全不只是防泄密。一个没有刹车的 agent，哪怕初衷只是帮你读个文件，也能把你的钱包读穿。

这次还算温柔的。它只是在读文件，没有写操作，没有网络请求，没有删东西。如果那天它的循环体不是「读文件大小」而是「删除临时文件」或者「发送 HTTP 请求」呢？如果它把某个 API key 当成参数传进了一个外部服务呢？

安全性确实重要。不是怕它偷你钱，是怕它哪天抽个风，把你送进去。

所以，有没有谁能还我的血汗钱
